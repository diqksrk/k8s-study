# kubectl 치트시트 (PowerShell 기준)

## 보기

```powershell
kubectl get pods                       # 파드 목록
kubectl get pods -o wide               # IP · 노드까지
kubectl get pods -w                    # 바뀌는 대로 계속 보기 (Ctrl+C 로 끝)
kubectl get pods --show-labels         # 레이블까지
kubectl get pods -l app=demo           # 레이블로 골라 보기
kubectl get deploy,rs,pods,svc         # 여러 종류 한 번에
kubectl get pod <이름> -o yaml         # 전체 내용 (spec = 원하는 상태, status = 실제 상태)
kubectl describe pod <이름>            # 자세히 + 맨 아래 Events
kubectl explain pod.spec.containers    # 필드 설명
```

## 만들고 지우기

```powershell
kubectl apply -f <파일 또는 폴더>       # 만들기 · 고치기 (파일이 기준)
kubectl delete -f <파일 또는 폴더>
kubectl delete pod <이름>
kubectl delete pod -l app=other        # 레이블로 골라 지우기
```

## 앱 들여다보기

```powershell
kubectl logs <파드>                    # 로그
kubectl logs <파드> --previous         # 직전에 죽은 컨테이너의 로그
kubectl logs deploy/demo               # 디플로이먼트의 파드 하나 골라서
kubectl exec -it <파드> -- sh          # 안으로 들어가기 (exit 로 나오기)
kubectl exec curl -- curl -s http://demo/     # 안에서 명령 하나만
kubectl port-forward pod/<파드> 18080:8080      # 내 PC 18080 → 파드 8080
kubectl port-forward svc/demo 18080:80          # 내 PC 18080 → 서비스 80
```

## 디플로이먼트

```powershell
kubectl scale deployment demo --replicas=5
kubectl rollout restart deployment demo    # 파드를 새로 띄우기 (설정 다시 읽기)
kubectl rollout status deployment demo
```

## 서비스

```powershell
kubectl get svc
kubectl get endpointslices -l kubernetes.io/service-name=demo   # 서비스 뒤의 파드 IP
kubectl describe svc demo
```

## 접속 · 권한

```powershell
kubectl config set-context --current --namespace=<내 네임스페이스>
kubectl config view --minify             # 지금 쓰는 클러스터 · 네임스페이스
kubectl auth can-i --list                # 내가 할 수 있는 일
```

## PowerShell 에서 주의할 것

- `curl` 은 다른 명령의 별칭입니다. 내 PC 에서 칠 때는 꼭 **`curl.exe`**.
- 시크릿 값 풀어 보기 (`base64 -d` 가 없어서):

  ```powershell
  $b64 = kubectl get secret demo-secret -o jsonpath='{.data.APP_PASSWORD}'
  [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String($b64))
  ```

- 같은 명령 여러 번: `1..6 | ForEach-Object { kubectl exec curl -- curl -s http://demo/pod }` (Mac: `for i in {1..6}; do kubectl exec curl -- curl -s http://demo/pod; done`)

## 고장 났을 때 보는 순서

1. `kubectl get` — 상태
2. `kubectl describe` — 맨 아래 Events
3. `kubectl logs` (`--previous`)
4. `kubectl exec` — 안에서 직접

| 상태 | 뜻 | 먼저 볼 곳 |
|---|---|---|
| `Pending` | 아직 노드에 배정이 안 됨 | describe 의 Events |
| `ErrImagePull` / `ImagePullBackOff` | 노드가 이미지를 못 받음 | describe 의 Events (이미지 이름 · 태그) |
| `CreateContainerConfigError` | 컨테이너에 넣을 설정이 없음 | describe 의 Events (컨피그맵 · 시크릿 이름 · 키) |
| `CrashLoopBackOff` | 앱이 떴다가 계속 죽음 | `logs --previous` |
| `Running` 인데 접속 안 됨 | 서비스 연결 문제 | 엔드포인트 슬라이스, 셀렉터, targetPort |
| `get pods` 에 파드가 아예 없음 | 내 칸의 쿼터(파드 15개)가 참 | `kubectl describe rs` 의 Events (exceeded quota) |
| `kubectl logs` 가 거의 비어 있음 | 앱이 로그를 파일로만 씀 | `kubectl exec <파드> -- tail <로그 파일>` (재시작하면 파일도 사라짐) |
