# 접속 가이드 (실습 0 을 자세히 · 막힐 때)

스터디를 시작할 때 1:1 로 받은 파일로 [HANDS_ON.md](../HANDS_ON.md) 의 '실습 0. 준비 · 접속' 을 합니다. 이 문서는 그 단계를 조금 더 자세히 적고, 자주 막히는 곳을 모았습니다. 10분이면 끝납니다.

받는 것은 아래와 같습니다. 다운로드 폴더에 저장합니다. AWS 계정은 필요 없습니다.

- `kubectl.exe` (Windows 만 · Mac 은 brew 로 설치)
- 내 접속 파일 `<아이디>.kubeconfig` (내 네임스페이스 `k8s-study-<아이디>` 가 이미 들어 있습니다)

> 접속 파일에는 내 네임스페이스에 들어가는 열쇠(토큰)가 들어 있습니다. 다른 사람에게 넘기지 마세요.

## 1. kubectl 설치

**Mac 이면** `kubectl.exe` 대신 터미널에서 아래 두 줄을 치고, 터미널을 닫았다가 새로 엽니다. 두 번째 줄은 실습 명령을 줄 끝 `# 설명` 까지 붙여 넣어도 에러가 나지 않게 하는 설정입니다. 2번의 `$HOME\.kube` 는 Mac 에서 `~/.kube` 입니다(`mkdir -p ~/.kube` · `cp <아이디>.kubeconfig ~/.kube/config`).

```bash
brew install kubectl
echo 'setopt interactivecomments' >> ~/.zshrc
```

**Windows 면** 받은 `kubectl.exe` 를 내 계정 폴더에 두고 PATH 에 넣습니다. 관리자 권한은 필요 없습니다. PowerShell 에서 받은 파일이 있는 폴더(다운로드)로 이동한 뒤:

```powershell
New-Item -ItemType Directory -Force $HOME\bin | Out-Null
Copy-Item .\kubectl.exe $HOME\bin\
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$userPath;$HOME\bin", "User")
$env:Path += ";$HOME\bin"
```

마지막 줄은 지금 창에도 바로 적용하는 줄입니다. 이 줄을 빠뜨렸으면 터미널을 닫고 새로 엽니다. 확인:

```powershell
kubectl version --client
```

## 2. 접속 파일 넣기

먼저 이미 쓰고 있는 설정이 있는지 봅니다:

```powershell
Test-Path $HOME\.kube\config
```

- `False` 이면 그대로 복사:

  ```powershell
  New-Item -ItemType Directory -Force $HOME\.kube | Out-Null
  Copy-Item .\<아이디>.kubeconfig $HOME\.kube\config
  ```

- `True` 이면 덮어쓰지 말고 진행자에게 말해 주세요. 기존 설정을 지키면서 쓰는 방법을 알려 드립니다.

## 3. 확인하기

```powershell
kubectl get pods
kubectl auth can-i create deployments
```

이렇게 나오면 성공입니다.

```text
No resources found in k8s-study-<아이디> namespace.
yes
```

## 자주 막히는 곳

- `kubectl : 'kubectl' 용어가 ... 인식되지 않습니다` — 1번 뒤에 터미널을 새로 열지 않은 경우입니다.
- `Unable to connect to the server` — 회사망에서 클러스터로 가는 길이 막힌 경우입니다. VPN 을 켜고 끄며 다시 해 보고, 그래도 안 되면 진행자에게.
- `No resources found in default namespace.` — 받은 접속 파일이 아니라 다른 설정이 쓰이고 있습니다. 2번을 다시 확인하세요.
- 다른 사람 네임스페이스에서 `Forbidden` — 정상입니다. 내 네임스페이스 안에서만 만들고 지울 수 있고, 노드(서버)는 보기만 할 수 있습니다.
- `error: You must be logged in to the server (Unauthorized)` — 접속 파일이 잘못 복사됐거나 클러스터가 새로 만들어진 경우입니다. 진행자에게 새 파일을 받으세요.
